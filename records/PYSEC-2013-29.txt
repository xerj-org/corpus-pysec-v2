PYSEC-2013-29 PyPI/pycrypto — The Crypto.Random.atfork function in PyCrypto before 2.6.1 does not properly reseed the pseudo-rando
package: pycrypto
ecosystem: PyPI
versions affected:
  >= 0, < 19dcf7b15d61b7dc1a125a367151de40df6ef175 (GIT: https://github.com/dlitz/pycrypto)
  >= 0, < 2.6.1 (ECOSYSTEM)
aliases: CVE-2013-1445, GHSA-x377-f64p-hf5j
references:
  https://github.com/dlitz/pycrypto/commit/19dcf7b15d61b7dc1a125a367151de40df6ef175

  https://github.com/advisories/GHSA-x377-f64p-hf5j

The Crypto.Random.atfork function in PyCrypto before 2.6.1 does not properly reseed the pseudo-random number generator (PRNG) before allowing a child process to access it, which makes it easier for context-dependent attackers to obtain sensitive information by leveraging a race condition in which a child process is created and accesses the PRNG within the same rate-limit period as another process.
